# Prompt Studio 使用说明

## 启动

```bash
cd /Users/chch/Desktop/Prompt_Studio
pnpm install      # 首次
pnpm dev          # 打开 http://127.0.0.1:3000
```

数据保存在 `data/studio.db`（SQLite，已加入 .gitignore）。删除该文件即可清空 Studio 自己的运行记录；九立数据不受影响。

未保存的提示词草稿、输入选择、当前打开的结果和面板宽度保存在浏览器本地（localStorage），刷新页面不会丢失；换浏览器或清除站点数据后会重置。

## 项目

- 左侧「项目」下拉切换项目；「＋ 新建项目」可选「复制九立 P1~P4 提示词」（以九立项目各提示词当前最新版本为起点）或「空白（只有通用提示词）」。
- 运行、快照、标注按项目隔离；地址为 `/projects/<项目 ID>/playground`。

## 工作台怎么用（v1.3）

顶部有三种工作模式，默认是「结果检查」：

| 模式 | 什么时候用 | 页面 |
|---|---|---|
| **结果检查**（默认） | 看结果哪里错了 | 结果占满屏幕。顶部一条只显示当前输入（有标准答案时多一个徽章）、「更换输入」和「编辑提示词」；提示词版本和模型在最上面一栏。「更换输入」从左侧抽屉选，选完自动收起 |
| **提示词调试** | 改提示词、换输入、看请求预览 | 左边编辑，右边结果（就是以前的左右分栏） |
| **版本对比** | 改提示词前后各跑一次后对比 | 在页面里勾两次运行，下方直接显示差异（勾选框只在这个模式里出现） |

结果区按"先看重点，再看细节"排列（以 P1 为例）：

1. **第一行精简状态**：运行是否成功、几条商品、几条**模型报告问题**（规则 / 结构检查发现的另计为「规则 / 结构提示」）、**准确性能否评测**（没有标准答案时写「准确性未评测」——问题数 0 不代表字段都正确）、客户名称（编号小字）。右侧只有一个「只看有问题的行」。
2. **商品表**：默认核心字段、一行一条（过长的悬停看全文），有冲突 / 问题 / 已标注的格子才有角标。点行首 ▸ 展开这一行全部 25 个字段，有问题的排最前。
3. **待处理问题**：没有问题时只有一句话。
4. **折叠起来的**：「合计与读取情况」（标题上一句话概括，空表只写"没有记录"）、「更多统计」。JSON、结构校验、Token、执行信息都在「详情」页签。

P2 / P3 / P4 也一样：统计卡片收在底部「更多统计」。P4 只有一张「逐字段决策」表，默认显示 7 个核心列（委托行、字段、当前值、模型结果值、决策、核验状态、理由），点「全部列」看其余 7 列（含「模拟新值」）；「按委托行看全部 25 字段」默认收起。P3 的「请求候选池」默认收起。

检查一个字段：点格子或展开区里的字段 → 右侧显示字段名和模型值，下面只有三个按钮：
- **✓ 对**：直接记一条「标注正确」。
- **✗ 错**：原地展开三个框——正确值（可选）、错在哪（必选）、备注（可选），再点「保存标注」。
- **? 不确定**：同样展开，「错在哪」可不选。

标注单独保存，不改模型原始输出。已有标注列在面板最下面，可修改、删除、导出。

右侧字段卡片里还有（v1.3 M1）：
- **字段状态**：有值 / 明确无牌 / 原件空白 / 未识别到 / 无法辨认 / 有歧义。
- **实际输入**：这个字段的来源（原件第几页 / 哪个 Sheet）当时有没有进入模型——页图已发送、文本已发送、没有进入模型，或「未记录」（旧运行、仅渲染）。模型没给来源时写「不可追溯」。
- 表格显示的值和模型原始输出不一样时，会标明「Adapter 整理时转换」；「原始输出中的所在节点」可以展开看原样 JSON。

P2 / P3 / P4 的结果，顶部摘要下面会多一行「九立硬规则检查」：
- **没问题**：绿字「已对照 N 条九立硬规则，都没有违反」。
- **有问题**：红色方框逐条列出，例如「改了人工锁定的字段：OR_002 的 origin 已锁定，却被改为「中国」→「韩国」」。点一条就会定位到那一格，右侧可以直接标注。

这些规则都写在九立提示词里，系统拿这次的输入和输出直接对照得出，不是推测。检查内容包括：
- **P2**：入仓号是否捏造、是否重复建单、同一条记录是否被复制到多个入仓号、整箱重量是否被复制到每一行、有没读完的页却说读完了等；
- **P3**：跨客户匹配、凭数量凑配、复用已占用的查货行等；
- **P4**：改了人工锁定的字段、改了数量等交易字段、来源范围不完整却写值等。

直接粘贴的输出没有对应输入，会提示「没法做规则检查」。

手写字有没有认错、两件商品有没有被错合成一行，需要看原件图片才能判断，规则查不出来。这类问题请在结果里用「✗ 错」标注。

其他 v1.3 M1 变化：
- 「详情」顶部的**运行证据**：这次运行保存了哪些证据（实际请求、服务商回报的模型、是否有思考内容等）、缺了什么及影响；早期运行会如实标为「证据采集不完整」，不会补造。
- 模型输出的结构版本和提示词登记的版本不一致时，结果顶部会有提示。
- 「更换输入 → 示例」每个示例显示运行次数和被标为错误的处数，可筛「只能仅渲染」「只看运行过的」。
- 提示词调试里，有未保存修改时可展开看「已保存 vs 编辑中」的逐行差异；也会提示当前结果那次运行用的提示词和编辑区是否一致。
- 版本对比时，两次运行用的样本 / 输入不同，会醒目提示「输入不可直接比较」。

### 让 Codex / Claude Code 帮你诊断（v1.3 M2）

Prompt Studio 提供只读的 MCP 服务。接入后，编程 Agent 能按 Run ID 自己读取这次运行的全部证据，写出带引用的诊断报告。接入步骤见 [MCP接入说明.md](MCP接入说明.md)，大致是：

1. `pnpm mcp:grant create --principal claude-code` 发一个令牌（只显示一次）；
2. 按说明把令牌配置进 Claude Code 或 Codex；
3. 在结果页点字段，右侧点 **「复制 Agent 诊断指令」**，粘贴到 Agent 里。
4. Agent 诊断完会把报告交回来。刷新结果后点同一个字段，字段卡片里会多一行 **「AI 诊断：…」**，点开看建议和依据。这是 AI 的推测，不会改你的标注。

网页里暂时不能一键启动 Agent（需要单独的 Runner，后续阶段）。每次 Agent 读取都记入审计，可用 `pnpm mcp:grant audit` 查看。

### AI 的修改建议（v1.3 M3）

- **正式版本**：版本下拉框里标「【正式】」的那个。你平时「保存为新版本」**不会**改变它。
- **修改建议**：Codex / Claude Code 诊断出问题后，可以提出提示词修改，并先在几个样本上试运行。前提是给它的令牌加了实验权限，见 [MCP接入说明.md](MCP接入说明.md) 第 7 节。在你采纳之前，修改建议不会影响任何版本。
- **怎么看**：打开「提示词调试 → 修改建议」。每条建议先给一句结论（可以采纳 / 建议拒绝 / 先别急着采纳），再给「修好 / 变差 / 需要你看」三个数字。改了哪里、每个样本怎么样，点「查看详情」。
- **怎么定**：点「采纳」会保存成一个新版本，并设为正式版本；点「拒绝」则什么都不变，记录会保留。
- **系统会自动检查**：
  - 格式对不对；
  - 模型引用的原文是不是真在它说的位置（会打开原件核对）；
  - 你标过的字段有没有被改坏；
  - 有没有漏行；
  - P2 / P3 / P4 有没有违反九立的硬规则，比如入仓号捏造、跨客户匹配、改了人工锁定的字段。

小技巧：想让系统判断某个字段有没有被改坏，先在那个样本的结果里把关键字段标为「对」。

## 最常用：通用提示词 + 上传文件（v1.2）

1. 进入项目默认就是左侧最上面的「通用提示词」。九立 P1~P4 在下方「九立预设」里。
2. 在「提示词」页写下你要 AI 做什么（例如「逐个文件说明是什么单据、关键编号和金额」）。
3. 在「输入 → 上传文件」：把文件或**整个文件夹**拖进来，或点「选择文件夹」。
   - 子文件夹也会读取，文件名会带上相对路径（如 `资料/发票/invoice.pdf`）。
   - 隐藏文件、系统文件（`.DS_Store`、`__MACOSX`、`~$` 开头的临时文件）和不支持的格式会自动跳过，点「已跳过 N 个文件」可以看原因。
   - 九立预设下，材料类型（委托单 / 发票 / 箱单 / 查货文件）按文件名自动判断，不对可以改；通用提示词不需要类型。
   - 一次最多 100 个文件，单个 30MB，合计 300MB。
4. 点「运行模型」。模型声明支持看图（`MODEL_SUPPORTS_IMAGES=true`）时，PDF 和图片会**自动**逐页转成图片一起发送，扫描件也能读。
5. 结果区只有三页：
   - **结果**：九立预设显示业务表格；通用提示词回答 JSON 时显示 JSON 树，回答文字时直接显示文字。
   - **原始输出**：模型原文和发给模型的输入。
   - **详情**：运行信息、输入覆盖、结构校验等技术信息。出错或输入不完整时，结果顶部会有一行醒目提示。

## 跑通四类示例（不需要模型）

1. 左侧选 P1 / P2 / P3 / P4。
2. 「输入 → 示例」选一个示例。每个示例都标有来源：
   - 结构示例
   - 真实录制·非 Gold
   - 人工构造
3. 点右上角「▤ 仅渲染」。
4. 结果区三个标签：
   - **结果**：业务视图。点单元格、问题或关系边，右侧「来源与标注」会联动。
   - **原始输出**：选中的路径会高亮。可以切到「发给模型的输入」查看。
   - **详情**：运行信息（各种 Hash、版本、模型、输入记录）、输入覆盖，以及结构校验诊断（点路径跳到对应 JSON）。
5. 底部「运行历史」：
   - 回放：查看不可变的历史结果。
   - 重渲染：用当前适配器另存为一个新 Run。
   - 勾选两条记录：点「对比」看关键指标（状态、Token、耗时、Schema 错误数等）、实际发送提示词的逐行差异，以及输出 JSON 差异。
6. 标注：在右侧「来源与标注」点「对 / 错 / 不确定」。有标注的单元格显示「标」角标；可点「导出：CSV / JSON」下载本项目全部标注（含模型原值，供离线评测）。

推荐样本：
- P1「冲突 + 无牌/空白/0」
- P2「无仓号 + 同仓号多页」
- P3「一对多 + 多候选」
- P4「KEEP 无证据/FILL/UPDATE/CONFLICT」

## 真实模型运行（需要你操作）

1. 编辑项目根目录的 `.env.local`，填写：
   ```
   MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1   # 任意 OpenAI 兼容地址
   MODEL_NAME=qwen3.6-flash
   MODEL_API_KEY=你的密钥
   ```
2. 重启 `pnpm dev`。顶栏会显示模型名，「▶ 运行模型」按钮变为可用。`MODEL_NAME` 是默认模型。
   - 换模型：在「提示词」页的「模型」下拉框里选。列表从服务商实时读取（百炼约 90 个对话模型，按通义千问 / DeepSeek / Kimi / 智谱 GLM / MiniMax 分组；语音、画图、向量模型和带日期的固定快照不列出）。每个提示词各记各的选择，每条运行记录都写明实际用的模型。「修改建议」里的试运行（实验）固定用默认模型，不跟下拉框走，保证前后可比。
   - `.env.local` 里的能力声明（能否看图、输出上限）只针对默认模型；换用的模型一律显示「未声明」，需要看图请手动勾选「附带原件图片」。
3. 输入来源可以是「上传文件」、没有标「只能仅渲染」的示例、「更多 → 从九立导入」，或在「更多 → 粘贴 JSON」里填请求上下文后点「把请求存为输入」。切换到另一个提示词时，如果它还没选输入、而当前输入也适用，会自动带过去。先在「请求预览」确认实际发送的内容。
4. 密钥只在服务端使用，不会返回浏览器。失败的调用会保存为 MODEL_ERROR，不会显示假结果。
   - 点「运行模型」后立即登记一条「运行中」记录，模型在服务端后台调用；结果区显示已等待秒数，结束后自动显示结果。刷新或关闭页面不影响这次运行，重新打开会接着等待。运行期间仍可「仅渲染」，但同一 Prompt 不能重复发起运行。运行中可点结果区的「取消运行」停止等待（Run 记为已取消；服务商可能已开始处理并计费）。服务重启会把未完成的调用标为 INTERRUPTED。
   - 输出达到 max_tokens 被截断时，会提示「被截断（finish_reason=length）」，请调大 max_tokens 重跑。
5. 看图：模型声明支持看图时，「附带原件图片」默认跟随模型能力——输入里有 PDF / 图片就自动附带；也可以在「提示词 → 运行参数」里手动勾选或取消，点「恢复默认」回到跟随。原件会逐页转成 JPEG（长边 2000px），和文字一起发送。一次最多 20 页，可在 `.env.local` 用 `MODEL_MAX_IMAGE_PAGES=50` 调大（页数越多越慢、越贵）。
   - 2026-10-10 已用当前模型 qwen3.6-35b-a3b 实测：没有文字层的扫描 PDF，模型能逐字抄出图中内容（Run `run_88bf9ca3cdef475f`、`run_db2fde31b9714742`）。
   - 转换需要本机安装 `pdftoppm`（`brew install poppler`）。
   - Excel 原件不转图，会在警告中注明。
   - Run 只记录附带了哪些页和它们的 hash，不保存图片本身。
   - 原件经只读连接按授权读取，不做修改。

6. 模型能力声明（v1.1，可选，写在 `.env.local`）。不填时界面显示「未声明」，不当作支持：
   ```
   MODEL_SUPPORTS_IMAGES=true      # 已配置；true 时 PDF/图片自动附带，false 时勾选「附带原件图片」会在运行前被阻止
   MODEL_MAX_IMAGE_PAGES=20        # 一次运行最多附带的页图数，默认 20
   MODEL_MAX_OUTPUT_TOKENS=32000   # max_tokens 超过上限会被阻止
   MODEL_SUPPORTS_JSON_MODE=false  # 只作说明，不发送 response_format
   MODEL_SUPPORTS_THINKING=false   # 只作说明，不发送 thinking 参数
   STUDIO_USER=你的名字            # 标注人；不填为「本机用户」
   ```
7. 运行前请看「请求预览」里的「输入覆盖」卡片：列出每个文件实际发送了哪些页 / Sheet、多少字、几张图片。显示「不是完整输入」时（例如 PDF 超过 20 页只发了 20 页），这次结果不能当作完整材料识别评测。模板里有未登记的 `{{变量}}` 时会被阻止运行。
8. 失败或取消的运行，可在结果区点「原样重试」：用同一输入、同一提示词原文和参数新建一次运行，原记录保留。

## v1.1 新增的调试动作

- **样本库**：按来源分组，每行只显示名称和运行次数，特殊情况才加标签（「只能仅渲染」「有标准答案」）。搜索框可搜样本名、样本号、验收项（如 AT09）；来源 / 结构版本 / 能否真实运行 / 有无标准答案 / 是否运行过，这些筛选收在「筛选」按钮里。选中后显示一句话概况，素材、标签等在「更多信息」里。
- **重新运行示例**：示例里的结果是以前录下的。选中示例后，卡片上点「▷ 用当前提示词重新运行」，就用这个示例的输入、当前编辑区的提示词真实调用一次模型（会产生费用），结果作为一条新的运行记录显示；录下的旧结果不变。标「只能仅渲染」的示例没附带输入，不能重跑。
- **提示词编辑**：上方可切「编辑 / 阅读」。「编辑」是原文，可搜索（Enter 下一个）；「阅读」按 Markdown 排版显示（「一、」「【】」章节、以及「通用执行约定」这类单独成行的短标题显示为标题，编号条目显示为列表），只看不改。「复制全文」复制提示词原文。User 模板一般不用改，默认收起。底部显示行数和变量检查；保存版本时填「变更说明」。
- **表格**：点列标题排序（再点降序、第三次恢复原顺序，定位不受影响）；「只看有问题的行」；有冲突 / 问题的单元格带角标。
- **P3**：「请求候选池」列出模型实际收到的全部候选。正确的查货行不在池里，是召回 / 输入构造问题；在池里却没被选，才是模型裁决问题。
- **P4**：「按委托行看全部 25 字段」（默认收起）；本轮没核验的字段显示「本轮未核验」，锁定字段标【锁定】。
- **人工纠错标注**：在右侧「来源与标注」里点「对 / 错 / 不确定」；标「错」时必须选「错在哪」。P3 展开后还可以选标注类型「正确候选 / 错误关系」。「错在哪」共 13 类（输入缺页、预处理、看图识字、提示词规则、模型判断、候选召回、关系裁决、输出结构、显示映射、业务规则、标准答案有误、证据不足、暂时无法归因），旧标注的 8 类归因照常显示并注明「旧分类」。标注独立保存，不改模型原始输出；每次修改都留一版，点「修订 N 次」可看历史。
- **运行对比**：切到顶部「版本对比」，勾两条运行。顶部会给出「是否满足严格同条件」；差异分为新增 / 删除 / 变化 / 一致 / 无法对齐。没有 Gold 时只看差异，不算正确率。

### P1~P4 可重复查看的示例

## 上传原件（PDF / Excel / 图片）

- 「输入 → 上传文件」：拖入文件或文件夹（见上方「最常用」一节）。九立预设下材料类型按文件名自动判断（委托单 / 发票 / 箱单 → P1；查货文件 → P2），可改；可填客户名称，点「上传 N 个文件」。
- Excel（xlsx/xls）按 Sheet 抽取单元格，结构与九立 Demo 预处理结果一致；文字型 PDF 用 `pdftotext` 按页抽文字（需 `brew install poppler`）。
- 扫描件 PDF 和图片没有文字层：模型支持看图时会自动附带页图；关掉附带图片时会被阻断，不会只发文件名。
- 原件按内容 Hash 保存在 `data/materials/`（只属于 Studio，不写回九立），快照记录原件 Hash 与预处理版本。删除快照后，没有其他快照引用的原件会一并删除。
- 上传文件可用于通用提示词和 P1 / P2；P3 / P4 需要上游结构化结果。

## 九立只读连接

- `.env.local` 中 `JIULI_DEMO_ROOT` 指向九立 Demo 仓库根目录。Studio 只读打开 `demo-generated/mock/` 下固定的几个 JSON 文件，以及 `demo-generated/extracted/` 下的预处理文本。
- `JIULI_ALLOWED_CUSTOMERS`：当前操作者可访问的客户 ID（逗号分隔，`*` 表示全部）。服务端据此拒绝跨客户读取。
- 「输入 → 更多 → 从九立导入」：选客户 → 选任务和查货批次 → 核对「将带上的文件」（发票、箱单等辅助材料可取消勾选，不纳入快照也不发给模型；主委托文件与查货文件由任务/批次决定）→ 「只读读取并保存为输入」。输入记录存在 Studio 自己的数据库里。
- 需要更新时，在「输入 → 历史输入」点它的「刷新」：重新只读读取，生成一个新快照（标注「刷新自 …」），旧快照和旧 Run 不变。
- 快照列表只显示能用于当前 P1~P4 的快照；勾选「显示全部」可看到其余快照（不可选）。
- 每个快照可设「保留期限」（默认永久；可选 7/30/90 天后自动删除）或直接「删除」。删除只移除快照内容与材料记录，历史 Run 和模型原始输出保留，「运行信息」会标明快照已删除；删除后不能再用该快照重跑或重渲染。
- P1 会按九立 Demo 的单证分段带上发票 / 箱单页；与主委托文件为同一单证的副本不重复发送。
- **九立真实业务 API 目前未接通**。日后九立提供只读接口后，实现 `lib/connectors/types.ts` 中的 `JiuliReadonlyConnector` 接口即可替换，界面不用改。
