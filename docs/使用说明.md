# Prompt Studio 使用说明

## 启动

```bash
cd /Users/chch/Desktop/Prompt_Studio
pnpm install      # 首次
pnpm dev          # 打开 http://localhost:3000
```

数据保存在 `data/studio.db`（SQLite，已加入 .gitignore）。删除该文件即可清空 Studio 自己的运行记录；九立数据不受影响。

未保存的提示词草稿、输入选择、当前打开的结果和面板宽度保存在浏览器本地（localStorage），刷新页面不会丢失；换浏览器或清除站点数据后会重置。

## 项目

- 左侧「项目」下拉切换项目；「＋ 新建项目」可选「复制九立 P1~P4 提示词」（以九立项目各提示词当前最新版本为起点）或「空白（通用 JSON）」。
- 运行、快照、标注按项目隔离；地址为 `/projects/<项目 ID>/playground`。

## 跑通四类示例（不需要模型）

1. 左侧选 P1 / P2 / P3 / P4。
2. 「输入 → 样本库」选一个样本。每个样本都标有来源：
   - 结构示例
   - 真实录制·非 Gold
   - 人工构造
3. 点右上角「▤ 仅渲染」。
4. 结果区四个标签：
   - **可视化**：业务视图。点单元格、问题或关系边，右侧「来源与标注」会联动。
   - **原始 JSON**：选中的路径会高亮。可以切到「请求上下文」查看。
   - **结构校验**：校验状态与诊断，点 Pointer 跳到对应 JSON。
   - **运行信息**：各种 Hash、版本、模型和快照。
5. 底部「运行历史」：
   - 回放：查看不可变的历史结果。
   - 重渲染：用当前适配器另存为一个新 Run。
   - 勾选两条记录：点「对比」看关键指标（状态、Token、耗时、Schema 错误数等）、实际发送提示词的逐行差异，以及输出 JSON 差异。
6. 标注：在右侧「来源与标注」保存。有标注的单元格 / P4 字段显示「标」角标；可点「导出全部：CSV / JSON」下载本项目全部标注（含模型原值，供离线评测）。

推荐样本：
- P1「冲突 + 无牌/空白/0」
- P2「无仓号 + 同仓号多页」
- P3「一对多 + 多候选」
- P4「KEEP 无证据/FILL/UPDATE/CONFLICT」

## 真实模型运行（需要你操作）

1. 编辑项目根目录的 `.env.local`，填写：
   ```
   MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1   # 任意 OpenAI 兼容地址
   MODEL_NAME=qwen3.6-flash
   MODEL_API_KEY=你的密钥
   ```
2. 重启 `pnpm dev`。顶栏会显示模型名，「▶ 运行模型」按钮变为可用。
3. 输入来源可以是带 `ctx` 标记的录制样本（会自动建快照），或「从九立导入」。先在「请求预览」确认实际发送的内容。
4. 密钥只在服务端使用，不会返回浏览器。失败的调用会保存为 MODEL_ERROR，不会显示假结果。
   - 调用期间结果区显示已等待秒数，「运行历史」里有一条「运行中」记录；刷新页面后这条记录结束时会自动显示结果。服务重启会把未完成的调用标为 INTERRUPTED。
   - 输出达到 max_tokens 被截断时，会提示「被截断（finish_reason=length）」，请调大 max_tokens 重跑。
5. 视觉模型：在「模型」页签勾选「附带原件图片」后，构造输入引用的 PDF / 图片原件会逐页转成 JPEG（长边 2000px，最多 20 页），和文字一起发送。
   - 转换需要本机安装 `pdftoppm`（`brew install poppler`）。
   - Excel 原件不转图，会在警告中注明。
   - Run 只记录附带了哪些页和它们的 hash，不保存图片本身。
   - 原件经只读连接按授权读取，不做修改。

## 九立只读连接

- `.env.local` 中 `JIULI_DEMO_ROOT` 指向九立 Demo 仓库根目录。Studio 只读打开 `demo-generated/mock/` 下固定的几个 JSON 文件，以及 `demo-generated/extracted/` 下的预处理文本。
- `JIULI_ALLOWED_CUSTOMERS`：当前操作者可访问的客户 ID（逗号分隔，`*` 表示全部）。服务端据此拒绝跨客户读取。
- 「输入 → 从九立导入」：选客户 → 选任务和查货批次 → 「只读读取并创建隔离快照」。快照存在 Studio 自己的数据库里。
- 需要更新时，在「输入 → 已有快照」点该快照的「刷新」：重新只读读取，生成一个新快照（标注「刷新自 …」），旧快照和旧 Run 不变。
- 快照列表只显示能用于当前 P1~P4 的快照；勾选「显示全部」可看到其余快照（不可选）。
- 每个快照可设「保留期限」（默认永久；可选 7/30/90 天后自动删除）或直接「删除」。删除只移除快照内容与材料记录，历史 Run 和模型原始输出保留，「运行信息」会标明快照已删除；删除后不能再用该快照重跑或重渲染。
- P1 会按九立 Demo 的单证分段带上发票 / 箱单页；与主委托文件为同一单证的副本不重复发送。
- **九立真实业务 API 目前未接通**。日后九立提供只读接口后，实现 `lib/connectors/types.ts` 中的 `JiuliReadonlyConnector` 接口即可替换，界面不用改。

## 测试

```bash
pnpm test        # 单元/服务层验收（Vitest）
pnpm e2e         # 界面验收（Playwright，会先执行 next build，使用独立的 data/e2e.db）
pnpm typecheck
node scripts/build-constructed-fixtures.mjs   # 重新生成人工构造样本
```

## 代码结构

| 位置 | 作用 |
|---|---|
| `lib/pipeline/` | 解析 → Schema 校验 → Adapter → ViewModel 流水线（纯函数，不调模型） |
| `lib/schemas/` | v2 / v3 JSON Schema（Studio 依据文档推导，**非九立官方**）与注册表 |
| `lib/adapters/` | `jiuli-p{1-4}.ts`：每个文件含 v2 与 v3 两个确定性 Adapter |
| `renderers/*.json` | 规格包原始 v2 渲染配置（未修改）；`renderers/v3/` 为新增的 v3 配置 |
| `components/renderers/` | 白名单组件：data-table、issue-list、relation-canvas、field-diff、evidence-viewer、summary-strip |
| `components/views/business-view.tsx` | 四种布局（按 RendererConfig 组合白名单组件） |
| `components/playground/` | IDE 三栏界面、JSON 树、结果标签、历史、对比 |
| `lib/connectors/` | 九立只读连接（Demo 文件实现 + 真实 API 占位），**接口上没有写方法** |
| `lib/input-builders/` | 由快照显式构造 P1~P4 请求 |
| `lib/models/` | OpenAI 兼容模型网关（服务端） |
| `lib/repositories/` | SQLite 存储：PromptVersion / Snapshot / Run / Annotation（原文与版本不可修改） |
| `lib/runs/service.ts` | 仅渲染 / 模型运行 / 重渲染 |
| `prompts/jiuli-v3/` | 复制自九立 Demo 的 P1~P4 v3.0 原文（作为初始版本；文件内容改动后，服务启动时自动追加为新版本，不覆盖旧版本） |
| `fixtures/` | 样本，见 `fixtures/README.md` |
