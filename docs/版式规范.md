# 版式（Layout）规范 v1

目的：让「通用提示词」的 JSON 输出按业务想要的样子显示，不改提示词、不改模型原始输出。

## 原则
- 版式只含 JSON Pointer 路径和显示名，**不含代码或表达式**（含 `=>`、`function(`、`<script` 的一律拒绝）。
- 版式按提示词保存，**只追加**（`prompt_layouts` 表，`layout_version` 递增，当前版式 = 最新一条）。
- 渲染在显示时即时计算：旧运行换版式后立即按新版式显示；对不上时退回 JSON 树并提示。
- 目前只用于通用提示词（`GENERIC_JSON`）；九立 P1~P4 的渲染不动。
- 文字一律按纯文本显示，不执行 HTML。

## 四种版式
| kind | 必填 | 显示 | 复用组件 |
|---|---|---|---|
| table | itemsPath, columns[{label,path,kind?}] | 一行一条记录 | 现有 DataTable |
| cards | itemsPath, titlePath, fields[{label,path}]，可选 badgePath | 每条一张卡 | 新：卡片列表 |
| checklist | itemsPath, titlePath，可选 statusPath/passValues/severityPath/detailPath | 通过/未通过 + 严重度 | 现有问题列表 |
| report | sections[{title,path}] | 按章节排版的长文，可复制 | 新：报告文档 |

## 路径
- `itemsPath`：指向数组的绝对路径（`/items`；根就是数组写空串 `""`）。
- 其余 `path`：相对每一项（`/name`；空串表示这一项本身）。report 的 `path` 是绝对路径。

## 对不上时
- itemsPath 找不到或不是数组 → 「版式没对上」，退回 JSON 树。
- 个别字段缺失 → 该格显示「（空）」，不报错。

## 代码位置
- 类型与校验：`lib/layouts/types.ts`
- 解释器（版式 + JSON → 显示数据）：`lib/layouts/apply.ts`
- 保存：`lib/repositories/layouts.ts`，接口 `/api/prompts/[id]/layout`
- AI 生成：`/api/prompts/[id]/layout/generate`
