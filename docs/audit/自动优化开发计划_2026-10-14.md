# 自动优化（Optimization Session）开发计划 · 2026-10-14

对应 v1.3 §11 与 §14 M4 的前半部分。网页一键启动 Agent（§9 Runner）不在本次范围。

## 已定的产品决定（用户确认）

1. **谁来跑**：用户在网页点「开始」，系统生成一段指令；用户粘贴到 Claude Code / Codex，由 Agent 一轮轮诊断、改、试运行。轮数、调用次数、停止条件全由服务端强制，Agent 绕不过。
2. **变差怎么办**：违反九立硬规则（漏行、跨客户、改了锁定字段等）立即停止；其他变差算「这一轮没进展」，还有预算就继续。
3. **入口**：在标了「错」的字段面板里，点「让 AI 自动修」。进行中的状态与结果显示在「修改建议」页签。

## 一次自动优化的完整流程

1. 用户把某个字段标为「错」，点「让 AI 自动修」，填写：
   - 回归样本（勾选同一提示词的其他样本）；
   - 最多调用模型次数（必填）；
   - 最多轮数（默认 3，上限 5）。
2. 系统自动做三件事：
   - 建一个数据集版本：当前样本为 dev，勾选的样本为 regression，冻结当时的标注作为标准答案；
   - 做证据预检；
   - 创建会话，给出「复制给 Agent 的指令」。
3. Agent 按会话行动：
   - 读证据 → 提交诊断；
   - 如果是提示词问题：创建候选 → 跑试运行 → 系统自动评判 → 决定下一步。
4. 结束时，「修改建议」页签显示停止原因和最好的那条候选；采纳或拒绝仍由人决定。

## 状态机（§11.2）

| 状态 | 含义 | 怎么离开 |
|---|---|---|
| CREATED → EVIDENCE_CHECK | 创建时同步预检：Run 存在、目标字段有「错」标注、输入完整 | 通过 → DIAGNOSING；不通过 → BLOCKED |
| DIAGNOSING | 等 Agent 提交诊断 | 归因是非提示词问题 → NON_PROMPT_ISSUE；证据不足（EVIDENCE_INSUFFICIENT / UNKNOWN / 结论不是 CONFIRMED）→ BLOCKED；提示词可修 → CANDIDATE_DRAFT |
| CANDIDATE_DRAFT | 等 Agent 创建本轮候选并试运行 | 跑试运行 → EXPERIMENTING；轮数已满 → STOPPED |
| EXPERIMENTING | 试运行进行中 | 完成 → EVALUATING；失败 → STOPPED（EXPERIMENT_FAILED） |
| EVALUATING | 系统根据报告自动决定（瞬时） | 见下面的「每轮评判」 |
| READY_FOR_REVIEW | 达标，等人审批 | 采纳 → APPROVED；拒绝 → REJECTED |
| 终态 | NON_PROMPT_ISSUE、BLOCKED、STOPPED、APPROVED、REJECTED | — |

- **非提示词问题**（§11.1）：INPUT_MISSING_PAGE、PREPROCESSING_ERROR、CANDIDATE_RECALL_ERROR、SCHEMA_CONTRACT_ERROR、ADAPTER_MAPPING_ERROR、INCORRECT_GOLD。
- **随时可以停**：用户取消 → STOPPED（CANCELED），同时停掉进行中的试运行。

**每轮评判**（用这一轮试运行报告，按顺序判断）

1. 有硬规则闸门（`hard_gates`）→ STOPPED（HARD_REGRESSION）。
2. 报告结论是「可供人审」→ READY_FOR_REVIEW。这一轮的候选就是最佳候选。
3. 计算本轮得分 = 修好的样本数 − 变差的样本数。比之前最好的高，就记为最佳候选，并把「连续没进展」清零；否则「连续没进展」加 1。
4. 达到最多轮数 → STOPPED（MAX_ITERATIONS）。
5. 连续没进展达到上限（默认 2）→ STOPPED（NO_PROGRESS）。
6. 剩余调用次数不够再跑一轮（按上一轮实际用量估算）→ STOPPED（BUDGET_EXHAUSTED）。
7. 以上都不满足 → CANDIDATE_DRAFT，进入下一轮。

**整体超时**：默认 60 分钟。每次读取或操作会话时检查，超时 → STOPPED（TIMEOUT）。

## 服务端强制的约束

- 同一个提示词同时只能有一个进行中的会话。
- **带会话的候选：**
  - 只能在 CANDIDATE_DRAFT 状态下创建，每轮一个；
  - 基于会话开始时的正式版本。
- **带会话的试运行：**
  - 样本固定为会话的目标样本加数据集的 regression 层；
  - 用会话的数据集评判；
  - 计划调用次数加上已用次数超过上限就拒绝，不调用模型。
- 诊断报告在 DIAGNOSING 状态下才推动状态；其他时候提交只作记录。
- 状态更新用版本号做乐观锁，两个 Agent 同时操作时只有一个成功。每次变化都追加一条事件，事件只增不改。
- Agent 仍然没有采纳工具；采纳或拒绝最佳候选时，会话随之进入 APPROVED / REJECTED。

## 不做的事

- 网页一键启动 Agent（§9 Runner），下一阶段再做。
- 按金额控制预算：服务商不返回价格，改为按调用次数。
- 候选基于上一轮候选继续改：每轮都从正式版本出发，Agent 可以在一次修改里带上之前的改动。
- 网页上单独的数据集管理页面：数据集只在开始自动优化时顺带创建。
