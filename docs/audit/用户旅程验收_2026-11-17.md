**九立 P1、P2 和通用提示词可以日常使用；P3、P4 只有会拼 JSON 的人（或 AI）能用，业务人员走不通。**

## 发现的问题

### 影响使用（建议修）

1. **P3 / P4 不能从 P1、P2 的结果生成输入。** 要手工按固定结构拼 JSON：商品池要编 `W-入仓号-G1`、`P-入仓号-1-1` 这类标识，P4 还要每个委托行拼一份。上次 P3/P4 测试是 AI 写脚本通过接口导入的。粘贴后存成的输入一律叫「粘贴的请求」，没法起名。
2. **全站时间显示的是 UTC，比新加坡时间慢 8 小时。** 运行历史、标注、版本、输入列表都是。例如上午 10:02 的标注显示 02:02；早上 8 点前的运行日期还会显示成前一天，按日期搜索也按 UTC 匹配。原因：界面直接截取数据库里的 UTC 字符串（`started_at.slice(...)`、`created_at.slice(...)`，约 20 处）。
3. **在「更换输入」抽屉里只是点开「示例」或「从九立导入」页签，当前输入就被清空。** 已复现：P1 当前输入是上传的委托单，打开抽屉点一下「示例」页签、什么都不选就关掉，顶部变成「还没选输入」，运行按钮变灰。原因：抽屉的页签同时决定输入方式（`inputMode`），切页签等于换了输入。这时还会同时出现「当前结果来自上次运行（与未保存/未运行的编辑不同）」，它和「提示词与编辑区一致」互相矛盾：这条横幅其实是输入变了触发的（`playground.tsx` 的 `dirty` 同时比较输入），文字却说是编辑不同。
4. **【正式】版本还停在 v3.0-fix1。** 你实际在用 v5.3，界面上除了「采纳修改建议」没有别的办法改正式版本。影响：AI「修改建议」以正式版本为底稿（`lib/optimization/service.ts:113`），现在让 Agent 提建议，它会在旧的 v3.0-fix1 上改。

### 小问题（顺手可改）

- P2 问题列表显示「入仓号 26020161 · hw · 手写记录」，`hw` 是英文字段代码。
- 通用提示词的标注抽屉显示「选中：r1」「c2」「无业务视图，无法定位来源」，应该显示「第 2 行 · 分类」。
- v15 输出的每个字段都用橙色写「不可追溯：模型没有给出这个字段的来源」。v15 本来就不输出字段来源，这条对每个字段都成立，等于噪音。
- 粘贴 JSON 的占位文字还是 `{"schema_version":"jiuli-ai-v3", ...}`，v15 已经不用这个格式。
- 「提示词调试」里，「当前结果用的提示词与编辑区不同」左右两边各说一遍。
- 模型设置：没改服务地址，点「测试连接」也提示「请填写密钥（换了服务地址需要重新填写）」。这是有意不复用 `.env.local` 的密钥，但提示语不对，密钥框也没写「已配置」。
- 外发确认用浏览器原生确认框，能用，但和其他弹窗风格不一致。
- 通用提示词空状态写「开始识别」，客服工单这类场景不叫识别。
- 保留期限下拉里「永久」和「永久保留」重复。
