## 1. 两种工作模式实际能完成什么（M0 验收）

截图在 `docs/audit-shots/m0-*.png`。

**结果检查**（默认模式，截图 `m0-check-mode-p1-fixture.png`、`m0-real-run-p1-sc08.png`）

1. 左侧点 P1，再点「更换输入」打开抽屉，选「示例」→「SC-08 · P1」。抽屉自动收起，结果占满主区域。
2. 顶部点「运行模型」，真实调用 qwen3.6-35b-a3b，等待约 49 秒。
   - 生成 Run `run_a02aa2b093634c1a`。
   - 结果显示「模型运行成功 · 2 条商品 · 0 条已报告问题 · 准确性未评测」。
3. 商品表默认显示核心字段，可切换到 25 字段，也可展开单行查看。
   - 点单元格会打开证据抽屉，里面有当前值、json_pointer、来源证据、「这个值对 / 错」和标注表单。
4. 问题卡可以定位到行和字段。「合计与读取情况」默认折叠（只有 P1 如此）。
5. 不能做的事：
   - 抽屉里看不到字段级的实际输入覆盖、原始输出节点和标注历史。
   - 没有 Agent 诊断入口。
   - 「仅渲染」的结果也写着「运行成功」。
   - 问题数把模型报告的和规则发现的混在一起，例如构造样本显示「4 条已报告问题」，其中 1 条其实是 Gold 行数规则。

**提示词调试**（截图 `m0-debug-mode-p1.png`）

1. 左边是提示词编辑器，有章节目录、搜索、行号、版本下拉、保存新版本（名称 + 变更说明）和变量检查。
2. 输入页签可以上传文件或文件夹、选示例、从九立导入，也有请求预览。
3. 右边是结果，分隔线可以拖动，比例会被记住。编辑器会标出「未保存草稿」。
4. 不能做的事：
   - 编辑器里没有「草稿 vs 已保存版本」的 Diff。
   - 编辑器里看不到「本次 Run 实际用的快照」这一层，只能去「详情 → 查看实际发送内容」看。

**版本对比**：能看到指标表、system/user 文本差异、按业务键对齐的 JSON 差异，以及「严格同条件」判定。没有 A/B 业务视图并排，也没有「修复 / 退化 / 未判定」。
