## 四、未完成 / 缺失

1. **九立真实业务只读 API**：外部依赖，接口不存在。
2. **PDF/Excel 文件导入**：PRD §1.2 要求"离线导入 JSON / PDF / Excel 为同等一等公民"，目前只能导入 JSON。
3. **<1280px 布局切换为页签**（PRD §5.4）：代码里没有任何响应式断点。1024px 宽度下不出现横向滚动，但三栏会被挤压。
4. **快照到期删除、脱敏策略**：`redaction_policy` 固定为 `NONE_LOCAL_ONLY`。
5. **项目管理**：只有一个种子项目，侧栏里写死了"九立 AI 核对"。
6. **证据按页定位**：打开原文件只是整份文件，不会跳到对应页。

## 六、疑似假实现或不可用

- **没有发现伪造数据或假按钮。** 所有"未接通"都在界面上如实标出。
- 隐患如下：
  - 预览与实际发送不一致：会误导用户以为发的是 A，实际发的是 B，**违反核心原则**。
  - 标注：功能是真的，但没有消费出口，等于摆设。
  - 历史表：当前 Prompt 没有 Run 时会回退显示**全部** Run，容易让人误以为是当前 Prompt 的。
  - 重渲染、保存版本按钮没有 try/catch：失败时界面没有任何反馈（`playground.tsx#rerender`、`PromptTab onSave`）。

## 七、核心用户路径验证

黄金路径（PRD §0.1）：选 Prompt → 导入输入 → 改 Prompt → 运行 → 看业务视图 → 定位错误 → 保存运行与标注。

| 步骤 | 结果 | 断点 |
|---|---|---|
| 选 P1~P4 | ✅ | — |
| 导入输入 | ✅ 样本 / 粘贴 / 九立导入 | P4 不能从九立导入；快照不按种类过滤 |
| 改 Prompt、存版本 | ✅ | 刷新丢失草稿；保存失败没有提示 |
| 预览实际发送 | ⚠️ | 样本模式下预览可能是另一个快照（已实测） |
| 运行模型 | ✅ 能跑 | 最长卡 300 秒且无进度；不能取消；关闭页面后结果只能到历史里找 |
| 看业务视图 / 定位 | ✅ | 截断时看不出原因 |
| 标注 | ⚠️ 能存 | 没有标记、不能导出，实际 0 次使用 |
| 迭代对比 | ⚠️ | 只有 JSON diff，看不到提示词改了什么 |

结论：**路径能走通，但"改 Prompt → 跑 → 对比"这条迭代循环不顺手、不可靠，而迭代正是这个工具的核心价值。**

## 八、开发计划

### P0（影响真实可用性和数据可信度）

**P0-1 预览与运行使用同一份输入** ✅ 已完成（`runSnapshotId()`；e2e「请求预览与真实运行使用同一份输入」）
- 目标：预览显示的就是点"运行"后实际发送的内容。
- 修改文件：`components/playground/playground.tsx`、`components/playground/editor-pane.tsx`（PreviewTab）。
- 做法：
  1. 抽出一个函数 `resolveRunSnapshot(ws)`，预览和运行共用它。
  2. 样本模式在选中样本时就建好快照（`/api/snapshots/import` 遇到相同内容会复用已有快照）。
  3. 切换输入模式时，清除不属于当前模式的 snapshotId。
- 验收：
  1. 先在九立导入一个快照，再切到样本模式选 SC-08 P1：预览显示构造器 `passthrough-snapshot-request`。
  2. 运行后 Run 的 `built_input_hash` 等于预览中的 input hash。
  3. 新增 e2e 覆盖这一点。
- 风险：粘贴模式没有请求上下文时，运行按钮要明确禁用并说明原因。

**P0-2 工作区持久化（刷新不丢）**
- 目标：刷新或重开页面后，草稿、输入选择、当前 Run、当前 Prompt 都能恢复。
- 修改文件：`lib/state/studio-store.ts`。
- 做法：用 zustand `persist` 中间件存到 localStorage，只存 `activePromptId`、`workspaces`、`lastMode`、布局；不存 runs 缓存。恢复后由 `runId` 重新拉取 Run。
- 验收：e2e 中修改提示词 → reload → 草稿还在，"未保存草稿"标记还在，上次结果能重新显示。
- 风险：要处理 SSR 水合闪烁（只在客户端恢复）；存储结构以后变动时要带版本号。

**P0-3 运行中状态 + 截断诊断**
- 目标：长时间运行有记录、有反馈；截断能看出原因。
- 修改文件：
  - `lib/runs/service.ts`
  - `lib/repositories/runs.ts`（增加只允许 RUNNING→终态的更新；raw_responses 仍然不可改）
  - `lib/models/openai-compatible.ts`
  - `components/playground/playground.tsx`
- 做法：
  1. 运行开始前先写入一条 RUNNING Run，结束后更新为终态。
  2. 保存 `finish_reason`；值为 `length` 时增加诊断 `MODEL_OUTPUT_TRUNCATED`。
  3. 界面显示已等待的秒数；历史列表能看到 RUNNING。
  4. 服务启动时，把遗留的 RUNNING 标记为 MODEL_ERROR（`INTERRUPTED`）。
- 验收：
  1. 单测：假服务返回 `finish_reason=length` → 出现截断诊断。
  2. 慢响应期间，`GET /api/runs` 能看到 RUNNING。
  3. AT22 相关测试不退化。
- 风险：runs 表目前只有插入，没有更新路径，需要明确限定可更新的字段。

**P0-4 补齐静默失败与错误码**
- 修改文件：
  - `playground.tsx`（rerender）
  - `editor-pane.tsx`（onSave）
  - `lib/connectors/snapshot-builder.ts`：改为抛 `ConnectorError("FORBIDDEN")`
- 验收：
  1. 跨客户请求返回 403 `FORBIDDEN`，补单测。
  2. 重渲染或保存失败时，顶栏显示错误信息。
